Brushblade Privacy Policy

Effective date: 2026-10-29
Last updated: 2026-11-11

This Privacy Policy explains how Brushblade (Chinese title 《字·斗》, the "Game") handles information.
The Game is developed and published by Eugene Wu, an individual developer ("I", "me", "the developer").

Contact: eugenewwj@gmail.com

1. Summary

  • The Game has no account system of its own, no chat, and no social features. I do not ask for your name, email, phone number, contacts, photos, or precise location. On Android, cloud save requires signing in to your Google Play Games account; the signed-in state is used only to read and write your save (see Section 2.1).
  • Your game progress is stored on your device. With cloud save on, it is also stored in your own iCloud (iOS) or Google Play Games (Android) account, which is managed by the platform provider. I do not run a server that receives your save data, and I cannot access your cloud save.
  • The Game shows optional rewarded video ads provided by Google AdMob. Ads only play when you choose to watch one in exchange for an in-game reward. There are no forced (interstitial), banner, or app-open ads.
  • All ad requests are sent as non-personalized ads requests. The Game does not ask for App Tracking Transparency permission on iOS and does not access the iOS Advertising Identifier (IDFA).
  • Google, as the ad provider, automatically collects certain device and usage data when an ad is requested or shown. This is described in Section 3.
  • The Game contains no in-app purchases.
  • To improve difficulty and content, the Game uses Google Firebase Analytics to collect anonymous gameplay statistics (for example which floor you reached, where a run ended, whether the tutorial was completed). This data contains no name or contact details and is not used for ad targeting; see Section 2.4. There is no crash-reporting SDK.

2. Information the Game handles itself

2.1 Game save data (your device and your own cloud account)

Your progress (collected characters, levels, in-game currency, chests, settings such as sound and battle speed, and the floor you reached) is written to a file inside the Game's private storage on your device. The file is integrity-protected to prevent tampering. It is not uploaded to me; I run no server that receives save data.

Cloud save (can be turned off in Settings). So that you can recover your progress after switching or reinstalling, the Game stores a compressed copy of the save (same content as above, integrity-protected, containing no account information) in your own platform cloud storage: iCloud key-value storage on iOS, and Google Play Games "Saved Games" on Android. This data lives in your Apple or Google account, is controlled by you and the platform provider, never passes through any server of mine, and I cannot access it. On Android, cloud save requires signing in to Play Games; the Game only uses the signed-in state to read and write this save and does not read or store your Google account details (name, email, avatar, and so on). If your progress differs between devices, you choose which copy to keep. At any time you can turn off "Auto Sync" in Settings → Cloud Save, or tap "Delete Cloud Data" to remove the cloud copy; progress on this device is not affected. For how the platform handles cloud saves, see Apple's and Google's privacy policies.

Your operating system may include the local save file in your own device backups (for example iCloud backup on iOS or Android backup), according to your device settings. Those backups are controlled by you and your platform provider; I have no access to them.

If you uninstall the Game, the save file on the device is deleted along with it; the cloud copy stays in your account, can be restored after reinstalling, and can be deleted beforehand in Settings → Cloud Save.

2.2 Time check

To make daily resets and chest timers fair, the Game asks its own time service (running on Cloudflare) for the current time when it starts and each time it returns to the foreground; if that fails, it reads the standard Date header from a well-known HTTPS website such as google.com. The request contains no identifiers and no game data. As with any internet request, the receiving server sees your IP address and basic technical information (such as the HTTP user agent). The Game's time service keeps no request logs, and I do not receive or store this information. If the request fails, the Game simply uses your device clock (or keeps its last successful time check).

2.3 Device identifier used for development testing only

The Game contains code that reads the device's vendor identifier (IDFV on iOS, or Unity's device identifier on Android) locally on the device, solely so that the developer's own test devices can skip ads during testing. This identifier is never transmitted by the Game, and in release builds it is not written to logs.

2.4 Anonymous gameplay analytics (Google Firebase Analytics)

The Game uses Google's Firebase Analytics SDK to collect anonymous gameplay statistics, for one purpose: understanding where players get stuck and which content is too hard or too easy, so the Game can be tuned. What is collected are gameplay events, such as: the app opening and going to the background, which screen was opened, the start and end of a tower run (floor reached, duration, outcome), the number of turns and the result of each battle, how far the tutorial got, which character card was picked, which chest was opened, which ad placement was watched, in-game-currency shop purchases, the outcome of cloud save syncs (success or failure reason, the choice made on a conflict, and whether iCloud or Play Games is used; never the save content), and the in-game numbers that accompany them (level, ink balance, number of cards, and so on).

Together with these events the Firebase SDK automatically collects: a randomly generated app-instance identifier (reset when you uninstall), device model and OS version, app version, language, country/region (an approximate location estimated from the IP address), and automatic events such as session duration. The Game does not send Firebase your name, email, contacts, precise location or any account information (the Game has none of these). Ad-personalization signals are disabled in Firebase; this data is not used to target ads to you or for ad attribution.

The data is processed by Google on my behalf and stored on Google's servers; what I see in the Firebase console are aggregate reports and anonymous event streams. Google's processing is governed by its own terms: https://firebase.google.com/support/privacy and https://policies.google.com/privacy .

If you are in the EEA, the UK or Switzerland, this collection only happens after you consent through the consent screen described in Section 3.1; if you decline or withdraw consent, the SDK stops collecting and uploading. Players elsewhere currently have no in-game switch; uninstalling the Game resets the app-instance identifier, after which earlier data can no longer be associated with your device.

3. Advertising (Google AdMob)

The Game uses the Google Mobile Ads SDK (AdMob) to show optional rewarded video ads, and the Google User Messaging Platform (UMP) SDK to request consent where required by law.

When the Game requests or shows an ad, Google's SDK may automatically collect and process the following on Google's behalf:

  • IP address, which may be used to estimate the device's general (coarse) location;
  • Device identifiers, such as the Android Advertising ID, App Set ID, or other app- or developer-scoped identifiers (on iOS, the IDFA is not available to the SDK because the Game does not request tracking permission);
  • Product interaction data, such as app launches, taps, and video views;
  • Advertising data, such as which ads were shown;
  • Diagnostic data, such as crash logs, app launch time, hang rate, and energy usage.

Google uses this data to deliver ads, measure ad performance, prevent fraud and abuse, and diagnose and improve its services. Because the Game requests non-personalized ads only, the ads you see are selected based on contextual information (such as the app itself and your general location), not on a profile of your interests. Note that non-personalized ads still use device identifiers and similar data for frequency capping, aggregated reporting, and fraud prevention.

Google's processing is governed by Google's own policies:

  • How Google uses information from apps that use its services: https://policies.google.com/technologies/partner-sites
  • Google Privacy Policy: https://policies.google.com/privacy
  • Google advertising technologies: https://policies.google.com/technologies/ads

3.1 Consent in the EEA, the UK and Switzerland

If you are in the European Economic Area, the United Kingdom, or Switzerland, the Game shows a consent message provided by Google (UMP) before any ads are requested. You can make or change your choices at any time from the Game's settings. Your consent choice is stored on your device by the UMP SDK.

3.2 Your controls

  • You never have to watch an ad. All ads are optional and only start when you tap a button to watch one.
  • On Android, you can reset or delete your Advertising ID in your device's settings (Settings > Privacy > Ads, or Settings > Google > Ads, depending on the device).
  • On iOS, the Game does not request tracking permission, so the IDFA is not shared.

4. In-app purchases

The Game currently has no in-app purchases. In-game currency and chests can only be earned by playing or by watching optional rewarded ads; they cannot be bought with real money and have no real-world value.

5. Legal bases (EEA/UK users)

For the limited processing described above:

  • Storing your save data on your device, syncing it to your own cloud account according to your settings, and checking the time are necessary to provide the Game you requested (performance of a contract / legitimate interests).
  • Anonymous gameplay analytics (Section 2.4) is based on your consent where consent is required (collected together with the ad consent), and otherwise on my legitimate interest in improving the Game.
  • Ad delivery by Google is based on your consent where consent is required, and otherwise on legitimate interests in funding a free game, as described in Google's policies.

6. Data retention

  • Save data remains on your device until you uninstall the Game or clear its data.
  • The cloud save remains in your own iCloud / Google Play Games account until you delete the cloud data in Settings → Cloud Save in the Game, or delete it through Apple / Google; retention is governed by the platform provider's policies.
  • I do not keep any copy of your data on servers I control.
  • Firebase Analytics event data is retained per app instance for 14 months, after which only aggregate reports remain; Google's retention as processor is described in the Firebase privacy documentation.
  • Retention of data collected by Google (AdMob) is described in Google's Privacy Policy.

7. Children

The Game is not directed to children under 13 (or the equivalent minimum age in your country) and is not designed for the Google Play Families program or the App Store Kids category. I do not knowingly collect personal information from children. If you believe a child has provided personal information through the Game, contact me at the address above.

8. Your rights

Depending on where you live (for example under the GDPR, UK GDPR, or the California Consumer Privacy Act), you may have rights to access, delete, correct, or object to the processing of your personal information, and to withdraw consent.

Because the Game does not send your save data or anything that directly identifies you to me, I generally hold no personal information that I can match to you that I could access or delete. Uninstalling the Game deletes all local game data and resets the Firebase app-instance identifier; the cloud save can be deleted in the Game under Settings → Cloud Save → "Delete Cloud Data". If you would like me to delete the analytics data associated with your app instance, contact me with the approximate time you played and your device model, and I will do my best to process it through Firebase's deletion interface; because I hold no identifier that maps an app instance to you, this may not be an exact match. For data processed by Google in connection with ads, you can exercise your rights through Google (see the links in Section 3). You may also contact me at the address above, and you have the right to lodge a complaint with your local data protection authority.

I do not sell your personal information and do not "share" it for cross-context behavioral advertising as those terms are defined under California law, other than the limited, non-personalized ad delivery by Google described above.

9. Security

Network requests made by the Game and by Google's SDK use encrypted connections (HTTPS/TLS). Both the local save file and the cloud save are integrity-protected.

10. Changes to this policy

If this policy changes, I will update the "Last updated" date above and post the new version at this address. For material changes, I will also give notice in the Game or on its store page.
